# AirPlay 屏幕镜像与视频投放

手机 + 车载浏览器模式的实验性接收器，使用独立的 Bonjour 名称、监听端口和配对身份。AirPlay 默认开启，打开 TiPlay 时自动启动接收器；本地网络权限未授予时不会启动。

## 使用

1. 让 iPhone、安卓手机和车载浏览器处于同一局域网。可以使用安卓手机热点；启动接收器不会更改当前 Wi-Fi、热点或 CarPlay 连接方式。
2. 打开已配对的 TiPlay HTTPS 浏览器页面。特斯拉的热点附加地址和本地网络权限要求沿用 [TESLA_BROWSER.md](TESLA_BROWSER.md) 与 [HOTSPOT_ADDRESS.md](HOTSPOT_ADDRESS.md)。
3. 打开安卓端 TiPlay，接收器会自动开始监听。
4. 屏幕镜像：在 iPhone 控制中心的屏幕镜像中选择 **TiPlay AirPlay**。
5. 视频投放：在支持 AirPlay 的视频应用中选择 **TiPlay AirPlay**。可以在 iPhone 或浏览器底部控制栏暂停、继续、跳转进度或结束投放；浏览器还提供倍速和有来源的字幕。直播等不可定位的媒体禁用进度操作。独立 JPEG/PNG 图片显示仅提供结束与全屏，不提供播放时间线。
6. 在 iPhone 上结束镜像/投放，恢复浏览器中的 CarPlay 画面。需要关闭接收器时，打开安卓端高级设置中的 **禁用 AirPlay**。

安卓端 **高级设置 → AirPlay → 禁用 AirPlay** 开关默认关闭。
打开后立即停止正在运行的 AirPlay 接收器，恢复仍有效的 CarPlay 画面，并禁止再次启动 AirPlay。
关闭开关立即重新启用接收器；此设置会保留，不要求重新连接 CarPlay。主页面与通知栏没有单独的 AirPlay 菜单或停止按钮。

纯音频 AirPlay 和 DRM 内容不在产品范围内。保留镜像必需的 legacy FairPlay 传输密钥协商，它与受保护内容的 FairPlay Streaming 许可不同。URL 视频及声轨由网页 Mediabunny／WebCodecs 解码、TiPlay 播放引擎输出，安卓仅处理协议和资源交接。镜像伴随音频支持 legacy RTP AES-CBC 与 AAC-ELD、44.1 kHz 双声道；只有镜像活跃时才解码与播放。ALAC、其他镜像音频格式与纯音频会话不播放，设备必须提供 AAC-ELD 解码器。

## 保留 CarPlay 并恢复画面

iPhone 切换到普通 AirPlay 时可能主动结束 CarPlay。投屏活跃期间不得启动或重建 CarPlay，已经排队的恢复任务也必须重新检查投屏状态；重新握手可能让 iPhone 切回 CarPlay 并结束视频。保留仍有效的控制会话；投屏结束后，已等待或被阻止的恢复任务立即重建已断开的 CarPlay，不再重复加入重试退避时间。禁用 CarPlay、关闭页面和会话归属检查仍优先于恢复。

有仍有效的 CarPlay 会话时，镜像、URL 视频和图片都通过 CarPlay 的 `changeModes` 借用 `mainScreen`，仅在 iPhone 的 `modesChanged` 确认屏幕归属接收端后接管画布与输入。发送成功或 RTSP 200 不是资源授权；增量通知中的 `resourceID=1`、`entity` 决定实际归属，不能用 `permanentEntity` 判断临时借用。借用使用 `transferType=3`，归还使用 `transferType=4`，不发送 `mainAudio` 借用请求。流程依据 [Apple 的资源管理说明](https://developer.apple.com/videos/play/wwdc2016/723/)。

启动接收器只开始监听。镜像在经过认证的密钥／计时 SETUP 后开始请求借屏，先释放已有触点；借用等待期间保留 CarPlay 画面与输入，不重建连接。镜像媒体 SETUP 在回复数据端口前有界等待授权，避免 iPhone 提前发送唯一的初始关键帧而被丢弃；超时拒绝接管并归还屏幕。URL 视频可准备资源，但授权前隐藏输出并暂停播放；图片编码器保留配置，在授权后请求关键帧。没有有效 CarPlay 会话时 AirPlay 可直接使用画布。

TiPlay 保留 CarPlay 控制连接、无线连接资源、必要保活、时钟和最新视频配置，不主动结束会话或触发显示尺寸重新协商。请求借屏的目标是让 iPhone 暂停后台 CarPlay 视频，实际带宽变化取决于 iOS。镜像和 URL 视频均与 CarPlay 音频混音，音乐、导航和提示音继续沿用 CarPlay 的归属；两路音乐可能重叠。镜像音频有独立生产者和浏览器通道，启停、重置和拥塞不清空 CarPlay 音频。禁用 CarPlay 音频不影响镜像声音。CarPlay 电话／Siri 麦克风需求期间，通话／Siri／导航只走安卓到车机的 HFP/SCO，网页保留音乐及 AirPlay 声音；蓝牙连接、失败和释放均不全局静音网页或清空这些声音的队列。

投屏接管后浏览器不再向后台 CarPlay 发送触摸、按键和手动适配请求。镜像数据／控制连接关闭、视频反向控制连接关闭、收到停止命令、播放结束或接收器停止时，先释放投屏画布，再 `unborrow` 归还屏幕；只有新的 `modesChanged` 确认 iPhone 拥有屏幕才恢复 CarPlay 显示、输入并请求关键帧。归还可能返回之前的接收端归属，不能假设发送后立即归 iPhone。iPhone 收回屏幕时立即停止 AirPlay 显示；URL 视频保留播放意图和定位版本，暂停反馈不能覆盖归属恢复后的继续播放意图。

安卓主线程先撤销 URL 播放会话或释放图片画布，再请求归还。恢复前再次确认没有更新的 AirPlay 生产者；旧输出的释放回调不能恢复到新投屏之上。资源输出与归属回调在同一个工作线程处理。这一流程不等待 Bonjour 清理计时器。浏览器的视频 HTTP 连接可继续接收新配置，无需重新配对或重新加载网页；已结束输出与迟到帧不能夺回画面。

这里保留的是 TiPlay 端的会话。iOS 如果主动终止 CarPlay 或更换网络，接收器无法恢复已经结束的会话；真车恢复行为仍需按具体设备验证。

安卓端的“已连接”表示保留的 CarPlay 控制会话；网页“正在连接”表示没有可用的视频配置。两者依据不同，不能仅凭网页提示判定控制会话已断开。

保留 CarPlay 会话不保证 iPhone 同时提供普通镜像的视频源。CarPlay 活跃时，iPhone 可能只建立普通 AirPlay 控制连接并发送心跳，尚未请求镜像视频流；此时接收端没有画面可供切换。控制连接成功或 iPhone 的勾选状态不能证明镜像媒体已经启动，共享 Bonjour 发布器也不能替代媒体协商。

显式 `TEARDOWN` 必须在清除镜像归属时通知监听状态，触发 CarPlay 显示恢复；只清除归属会使后续断连回调无法再恢复画面。恢复只由当前镜像所有者触发，旧连接不能结束新镜像。

初始 SETUP 的屏幕借用准备不占用 AirPlay 媒体归属；只有实际建立类型 96 或 110 才占用。没有媒体的控制连接可以继续发心跳，但不能阻挡另一条连接请求媒体。准备连接结束时仅释放自己的借用准备，旧连接不能结束已替换它的新镜像／视频。重新协商密钥释放自己的旧媒体归属，不关闭其他连接。

iPhone 锁屏与解锁可能重复发送相同镜像配置而不发送新的 IDR。尺寸与配置未改变时，接收器必须保留当前画布、解码 epoch 和预测链；无条件重建画布会让网页等待不存在的新关键帧。暂停期间仍消费密文以保持 CTR 位置，恢复后继续接收预测帧。

镜像数据通道结束立即释放画面，但不主动关闭对应的 RTSP 控制连接、计时服务或传输密钥。控制连接仍可回复 `TEARDOWN`，或在同一连接上接受新的镜像 `SETUP`；由 `TEARDOWN`、控制连接结束或接收器停止统一清理会话。控制连接保留原有读取超时，数据通道结束不会导致无限持有空闲会话。保留控制连接避免在 iPhone 发送停止请求前抢先截断控制回复。UxPlay 在完整包边界的 EOF 后还会继续监听原数据端口；TiPlay 需要新的 `SETUP`，不支持直接重连旧数据端口。

正常停止或连接关闭立即进入上述释放与恢复流程。静默掉线使用现有 TCP 存活检测：Android 10+ 尝试启用约 20 秒的失联检测窗口，不以没有视频帧判断断线；系统不支持调优时退回其 TCP 行为。它不是实测恢复时延保证。

## 实现与开源依据

以 [FDH2/UxPlay](https://github.com/FDH2/UxPlay) 的 `ec203121355220dd90278a369eeabb0b8ba4f14a` 为主要协议参考，固定版本便于核对实际处理路径，不能仅凭功能位名称或源码中的声明认定功能已实现。

复用 UxPlay 的 `playfair` 镜像传输密钥模块及传输握手回复表，保留许可证和出处；Android 侧的协议、发现、媒体和浏览器适配为 TiPlay 新文件。没有将 UxPlay 的桌面应用或 GStreamer 播放器搬入 Android。详见 [第三方说明](THIRD_PARTY_NOTICES.md) 和 [native 来源记录](../shared/src/main/jni/airplay/README.md)。

保持这个边界便于跟进 UxPlay 的协议修复。URL 视频使用随网页发布的 Mediabunny 解封装、WebCodecs 解码和 TiPlay 的 Canvas／Web Audio 播放引擎，Video.js 提供原生控件和皮肤。播放状态沿已配对的控制通道反馈给 iPhone，播放 ID 和命令版本隔离过期状态。控制栏提供播放、时间、进度及真实缓冲范围、倍速、字幕、加载图标、自动隐藏和停止，没有音量或全屏按钮。视频缓冲不会显示全屏等待界面。

- 屏幕镜像：独立的 legacy pair-setup / pair-verify、镜像传输密钥协商、SETUP / RECORD / TEARDOWN、NTP 计时和 AES-CTR 屏幕流。H.264 或 HEVC 配置与解密后的帧直接进入 `WebVideoHub`，按镜像头里的尺寸适配横竖屏，不在安卓端重新编码。HEVC 声明跟随现有 HEVC 设置，支持普通镜像的 `hvc1` 配置封装；浏览器仍必须支持对应 WebCodecs 解码器。横竖屏尺寸变化不等于实现了独立的 ScreenRotate 协议。镜像暂停标志保留最后画面并继续消费密文，恢复时不重置 CTR 状态。
- 视频投放：HTTP `/play`、`/reverse`、`/rate`、`/scrub`、`/stop`、`/playback-info`。沿用 UxPlay 的 `unhandledURLRequest` / `/action` FCUP 交换，让 iPhone 应用提供其持有的 HLS 播放列表和资源；请求按播放会话、对端、URL 和请求 ID 关联。播放或会话结束、被新播放替换时取消对应请求。不会通过资源加载器请求 `skd` 密钥或安卓本地文件。
  加载被中断时，同一播放会话、对端和 URL 的后续加载在原有有界截止时间内复用仍待完成的请求；等待超时后释放。已消费的 FCUP 正文不做跨请求缓存。安卓端检测资源内容确定 HLS，不依赖扩展名，递归改写子清单、片段、初始化段和普通 AES-128 密钥到配对验证的会话资源 ID，保留 Range 和受限跳转。媒体按需流式转发，只有有大小上限的清单／FCUP 响应在内存中处理。当前 iPhone 对端的 HTTP(S) 地址跳过安卓反代；网页直连需要 iPhone 提供可用的 CORS 和网络条件。

- 视频播放：网页 Mediabunny／WebCodecs 解码未受 DRM 保护的 MP4／HLS，TiPlay 管理输出和时钟；安卓不进行 URL 视频解码、转码或 PCM 输出。初始位置在媒体准备完成后应用，iPhone 滑块请求有短时合并；独立 seek 版本避免随后 pause／play 把新进度回滚。浏览器报告实际位置、倍率、准备状态、连续缓冲终点和可定位范围，缓冲期间保留播放意图，不伪造缓冲已满。
- 图片投放：HTTP `PUT /photo` 接收 JPEG/PNG，支持会话隔离的 `cacheOnly` / `displayCached`；输入大小、缓存总量、键长度与解码尺寸均有界。后台缩小图片后通过相同 Surface 链路呈现，并低频重复静态帧以允许新加入浏览器获取关键帧。停止后清空缓存；不实现幻灯片调度。
- 镜像声轨：参考 UxPlay `raop_buffer` 的逐包 CBC 解密及 `audio_renderer` 的 AAC-ELD AudioSpecificConfig。RTP 的 CSRC、扩展头与填充有边界检查，重复及迟到包丢弃，小幅乱序有有界等待；不请求 UDP 重传。不将 CarPlay 的 ChaCha20 音频解密套用到普通镜像。解码队列只保留短时实时音频，浏览器承担输出；RTP/NTP 时间锚点映射为安卓单调呈现时间并随 PCM 传给浏览器，与镜像视频共用源时钟；无有效锚点时退回到达播放。此路径仍不能宣称经过实机验证的精确声画同步。
- 后台与发现：默认启用的 connected-device 前台服务、CPU/Wi-Fi/多播锁；每个物理 IPv4 局域网接口使用一个主地址发布 Bonjour，定期跟踪热点地址变化。浏览器专用附加地址及接口别名不另建 Bonjour 实例，避免同一热点上的接收器互相判定名称冲突；不同物理接口使用不同主机名。接收器不需要 CarPlay 的 MFi 认证身份。启动期间允许同一局域网中的 iPhone 发起连接，不设置 AirPlay PIN；浏览器配对仍使用原有配对码。

所有功能仅面向安卓手机 + 车载浏览器，没有增加原生车机产品流程。

### 视频资源与进度反馈

iOS 应用可能只能逐个处理 FCUP 资源交换。反向 HTTP 对事件的确认不代表资源加载完成；必须等对应的 `/action` 响应、取消或原始截止时间到达，才能派发下一项。浏览器中断一个加载等待者后，交换仍可被后续相同加载复用，不能重置其截止时间；排队等待者也必须在前一交换到期时唤醒，避免已经没有等待者的请求阻塞队列。期限与队列边界以 [ReceiverResourceRequests](../shared/src/main/java/com/shilapi/xcertplay/receiver/ReceiverResourceRequests.kt) 为准。

iPhone 可以在提交 `/scrub` 后立即查询 `/scrub` 或 `/playback-info`。接收器须同步确认最新跳转目标，不能在合并窗口内回读旧位置；派发仍保留短时合并。待确认目标仅用于协议反馈，网页继续维护实际媒体时钟。新跳转替换旧请求，旧派发和旧版本报告不得撤销新目标；网页应用当前版本并报告就绪、非缓冲后，协议反馈再使用实际位置。等待确认期间不能把旧位置的缓存范围当成目标位置已经缓存。

Legacy `/playback-info` 的准备与缓冲标志使用 plist 整数 `0/1`；缓冲已满描述当前可播放缓冲，而非整个视频已下载。持续播放状态通过查询反馈，反向 HTTP 保留给 FCUP 与真实结束通知。合法的 `HTTP`／`EVENT/1.0` 反向响应必须作为响应消费，不能再回复请求错误。

### 保存诊断报告

接收器和播放器的诊断须经宿主日志进入会话文件，同时保留 logcat 输出。错误原文先过滤 URL、令牌及配对信息；格式化日志使用 `errorType`，浏览器报文中的 `errorName` 保持兼容，避免错误字段名被保存报告的设备名称过滤器误判。诊断只记录协议阶段、控制来源、位置、版本和缓冲元数据，不记录媒体内容或认证载荷。

普通接收器发布为 `TiPlay AirPlay`，CarPlay 发布为 `TiPlay`。两者同属 `_airplay._tcp`，但端口和能力不同，必须使用不同的服务实例名，避免 Bonjour 名称冲突及客户端缓存混用。

能力声明的权威来源是 [ReceiverCapabilities](../shared/src/main/java/com/shilapi/xcertplay/receiver/ReceiverCapabilities.kt)。图片能力来自 TiPlay 的 `/photo` 路径；不复制 UxPlay 的幻灯片或播放队列声明，其 HLS 缓存不等于播放队列。封面、DMAP 文本和进度通过有界 `SET_PARAMETER` 解析后立即丢弃，不保存内容或提供元数据显示。配对失败清除临时状态并关闭对应连接；不支持的 FairPlay 传输版本返回 501，损坏报文返回 400。

普通镜像保留 bit 14 的 legacy FairPlay 传输认证声明；关闭它可能使 iPhone 在配对后、传输密钥协商前结束连接。这不代表 DRM 视频支持；FairPlay Streaming 与 AES-GCM 能力仍不声明。

RFC2198 不在接收器支持范围内，bit 61 保持关闭；普通 UDP 音频接收不代表实现了 RED 解析或冗余恢复。

Bonjour 的功能位 30 表示同一 `_airplay` 端口也提供 RTSP 镜像入口；它与音频支持位 9 及功能位 26（Unified Advertiser 信息）不同。HTTP 图片/视频与 RTSP 配对、镜像共用监听端口，发现记录、`/info` 与 `/server-info` 保持此声明一致。音频格式声明保留已有的传输入口兼容性，不能据此认定每种格式均可解码；可播放镜像音频受上述 AAC-ELD 限制。`/info` 音频输入格式为零，不向普通 AirPlay 发送麦克风；CarPlay 录音使用安卓连接的车机蓝牙电话通道。类型 96 返回已绑定的数据和控制 UDP 端口，仅消费当前对端。单独停止类型 96 不结束仍有效的镜像；完整会话结束释放端口。没有旧式 RAOP 独立握手，因此不发布 `_raop`（AirTunes）。发现语义依据 [公开功能位说明](https://openairplay.github.io/airplay-spec/features.html) 和固定 UxPlay 的 [端口与功能位实现](https://github.com/FDH2/UxPlay/blob/ec203121355220dd90278a369eeabb0b8ba4f14a/uxplay.cpp)。

Legacy 镜像初始 SETUP 的 `eventPort` 为 0，不能填写接收器控制监听端口。`GET_PARAMETER volume` 返回 0 dB，避免要求 iPhone 静音镜像声轨；输出音量由浏览器与车辆控制。`/feedback` 是心跳，不能用它冒充关键帧请求。网页加入视频流必须等待可独立解码的 IDR；收到配置或持续转发加密流解出的帧，都不能单独证明网页已有画面。诊断仅记录帧数、IDR 数、Annex B 格式计数和音频报文数量，不记录媒体内容或密钥。

普通 AirPlay 的 NTP 报文使用固定本地时间基准，视频时间映射单独跟随 iPhone 时钟。iPhone 的计时基准可能是开机时间加 NTP 纪元，与安卓墙钟相差很大；同步视频时不能把这个偏移直接加到后续报文时间。每次计时样本得到的绝对偏移必须先扣除已应用的媒体偏移，再用于校正，否则持续同步会重复累加偏移。此路径不改变保留的 CarPlay 计时行为。

## 音画时间与播放策略

镜像音频的 RTP 采样时间不是绝对时间；必须使用控制通道的 RTP/NTP 锚点，映射到与镜像视频相同的安卓单调时钟。同步报文中偏移 4 的 RTP 采样值对应偏移 8 的 NTP，偏移 16 的采样值含发送端延迟，不能互换。UDP 音频按序号做有截止时间的短窗口重排，采样时间戳独立展开回绕；缺包不触发重传，也不能让之后的音频提前播放。

URL 视频的音画同步、解码队列、缓冲和 seek 由 TiPlay 播放引擎管理，使用音频播放时钟；没有音轨时使用单调时钟。数据不足时冻结进度和音画，缓冲范围来自当前可播放音画区间的交集。媒体 PTS 统一换算为相对秒数，HLS 的日期时间不能成为进度条或 iPhone 的位置。全局帧率设置仅影响 CarPlay 和 AirPlay 镜像，不改变 URL 视频的源帧率。修改帧率或 HEVC 更新镜像协商，不停止当前 URL 视频。

URL 视频画面由 [airplay-canvas.js](../site/play/airplay-canvas.js) 呈现到独立 Canvas，复用 CarPlay 的 WebGL2／WebGL 绘制器，无法创建 WebGL 时回退到 2D。Video.js 媒体适配器读取引擎的真实状态，不运行第二个 HTML 视频播放时钟。暂停保留最后画面，seek 显示目标帧，尺寸变化和 WebGL 上下文恢复后重绘；绘制缓冲不超过源视频的有效分辨率，不读取像素到 JavaScript。解码样本、队列、音频节点和 GPU 资源都有明确归属，过期 seek 回调只能释放自己的样本。

播放与暂停、seek、倍速变化保留同一源级 Input，避免 HLS 播放列表刷新后重新从零建立时间线；结束、失败、换源和图片接管释放 Input 并中止请求。直播暂停超过服务端保留窗口且目标片段未缓存时，旧位置可能已不可读取；不能伪造其缓冲或 seek 成功。支持的解码格式取决于浏览器实际 WebCodecs 能力，车载浏览器的资源占用与音画偏差仍需实车测量。

倍速通过 SoundTouch 变速不变调。网页状态的 `rate` 表示选中的正倍率，与 `playing` 分开；暂停保留该倍率，iPhone 的播放状态在暂停或结束时返回零。旧网页缺少 `rate` 的报告按正常速度处理。iPhone `/rate` 的零值暂停，支持范围内的正值设置倍率并继续播放；这些命令不能改变独立的 seek 版本。CarPlay 蓝牙语音路由不静音 URL 视频声音。

CarPlay 与镜像的网页实时流按未经补偿的源预期呈现时间平滑播放，Delta 上限和允许音画偏差以 [时间策略](../site/play/delay-plan.js) 为准。解码完成的视频帧按源时间重排并在上限内等待，超时帧在调度和实际绘制前丢弃；压缩视频保持解码依赖顺序。零上限不产生负的缓冲计划，提前提交余量用于给绘制留出时间；它不能让已经超时的帧恢复有效。传输背压和未提交画面的合并用于限制资源占用。音频保留源采样时间和独立播放队列，不阻塞画面。

Debug 保留编码、当前 FPS，以及带正负号的呈现偏差中间 90% 均值和最高 5% 均值；删除源预期时间／提交时间一行。实时流的源时钟仍供调度和诊断使用，不将网络到达时间伪装为源时间。

源呈现时间表示预期播放时间，并非明确的采集时间。因此提交偏差不能当作采集到实际屏幕显示的端到端延迟。并排录像应比较两端同一画面内容的变化；URL 视频两端独立的播放／暂停控制栏会混入控制命令与状态更新延迟，不能替代媒体路径测量。播放策略直接使用原始 Delta，不加入录像推算的固定补偿。实时流调度不额外估计或补偿目标设备的显示屏和扬声器输出延迟；Siri／通话期间的蓝牙 HFP/SCO 输出也不能由原始 Delta 推算实际声学延迟。

实时流实际端到端延迟仍需实机验证，原始 Delta 上限只约束源预期呈现时间到浏览器画面提交的时间差。缺失有效源时间的画面继续直接显示并标记源时间不可用，不伪造符合上限的时间戳。

音频传输携带每种音频流独立的 epoch、单调呈现时间和媒体模式；视频配置也携带相同的模式，用于选择各模式的缓冲上限。两条 HTTP 响应谁先到达都能选定策略，视频配置到达不能清空已经收到的新音频。同模式的尺寸或编码配置变化保留缓冲计划；模式切换选择新的策略。缺失或过期的源同步会退回到达播放，并计入 fallback 诊断，不能视为已实现源时间同步。浏览器连接重建清理全部待播数据；流内停止、暂停和重建由各自的有序重置处理。

## URL 视频字幕

字幕语法与 HLS 时间转换复用 [hls.js 的 WebVTT 实现](https://github.com/video-dev/hls.js/tree/master/src/utils)，由网页自托管；TiPlay 负责发现 master playlist 的 `EXT-X-MEDIA:TYPE=SUBTITLES`、认证资源获取和按播放引擎时钟激活 cue。字幕层只写入纯文本，不把来源内容作为 HTML 插入页面。

支持独立 WebVTT 与 HLS WebVTT 分段，包括 `X-TIMESTAMP-MAP`、MPEGTS 回绕、discontinuity 和 byte range。默认从每个 discontinuity 首字幕段建立到 `EXTINF` 相对时间轴的锚点；Mediabunny 已归一的时间不能冒充原始 MPEGTS。来源字幕与音视频使用不同起始偏移时，需要额外提供原始媒体时间锚点才能精确对齐。直播窗口刷新通过重叠的 media sequence 保留时间轴；丢失重叠锚点时停止更新该字幕轨，避免显示到错误时间。

仅在字幕轨启用时获取当前及邻近分段，并限制请求并发、响应大小和缓存；换源、关闭字幕和停止会取消待处理请求，迟到结果不能写回新会话。字幕获取或解析失败不应终止视频播放。嵌入 MP4 字幕、加密字幕分段和需要解封装的 fragmented MP4 字幕不属于这条 WebVTT 路径；没有可读取的字幕来源时不创建虚假字幕轨。

## 验证

新增回归覆盖双方配对签名、坏签名拒绝、跨非整块帧的 CTR 连续性、发现与 `/info` 能力一致、请求长度边界、镜像尺寸与加密码流、视频进度/速率、反向事件、FCUP 会话归属和断连取消、资源加载与重定向、CarPlay 配置保留/关键帧恢复、后台输入隔离以及入口不会断开 CarPlay。

原生边界检查可用 JDK 和 C 编译器运行：

```sh
python3 scripts/test_airplay_native.py
```

完整源码检查以 [AGENTS.md](../AGENTS.md) 和 [Android CI 工作流](../.github/workflows/android.yml) 为准。协议回归、原生 JNI 边界和模拟浏览器检查不能代替真实 iPhone 连接、Android 镜像音频解码／图片编码与车载浏览器验证。
