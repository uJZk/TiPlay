# TiPlay App 主页面设计

更新日期：2026-10-11。

状态：Markdown 设计稿，尚未应用到 App 代码。网页设计见 [网页配对页设计](WEB-PAIRING-DESIGN.md)。

## 页面合并

A01 首页与 A03 主设置合并为 A01「App 主页面」。连接状态、连接操作与日常设置在同一页面展示，不再通过首页上的“设置”按钮进入另一套主设置。

- A01：统一主页面，承载原 A01 和 A03 的功能。
- A03：取消独立页面编号和入口，内容并入 A01。
- A04：保留独立高级设置，承载视频、CarPlay 控制及诊断。
- 关于和语言选择保留为主页面入口。

## 第一屏的信息原则

用户原则：**一定需要设置，或有必要了解的选项，全放第一屏。**

第一屏直接呈现完成连接所必需的设置，以及理解当前状态和下一步操作所必需的信息。用户不应进入高级设置才能完成正常连接。合并首页与主设置时按这个原则重新安排内容，不简单拼接两份旧页面。

| 放置位置 | 内容 |
| --- | --- |
| 第一屏：连接状态与操作 | 当前阶段、连接失败原因、下一步操作、选择 iPhone、连接／重连／断开 |
| 第一屏：连接方式 | 无线／USB，以及当前方式必须填写的网络信息 |
| 第一屏：网络与地址 | 本机热点／同一局域网／车载热点或第三方 AP 选择、SSID 与密码、安全类型、安卓地址、必要的地址处理及授权操作 |
| 第一屏：浏览器连接 | 网页地址、配对码、连接链接、服务是否就绪、缺少的本地网络权限 |
| 第一屏：启动行为 | 打开 TiPlay 时是否自动连接及其说明 |
| 高级设置 | 帧率、HEVC、详细画面参数、驾驶侧、日志与诊断报告等调优和排障选项 |
| 简短辅助入口 | 高级设置、语言和关于；不占用大幅介绍区域 |

与当前方式无关的字段不显示；当前方式必需的字段直接显示，不通过折叠区隐藏。权限和恢复按钮仅在需要用户处理时出现。正常状态使用简短说明，详细错误在出错时显示。

首屏不放大幅品牌介绍、重复说明或完整技术状态日志。实施时用实际窗口验证核心连接区的首屏容纳情况；窄屏、矮屏和大字体允许滚动以保证必要字段可用，不以折叠、截断或缩小到难以操作的尺寸解决空间不足。

## 行为与去重

- 连接操作只在顶部状态区出现一次，不在设置底部再放一组相同按钮。
- 无线和 USB 使用同一个连接模式选择，不再同时放独立 USB 快捷按钮与相同设置行。
- 未连接时，“连接”使用当前连接配置；有待提交的连接设置时，“保存并重新连接”负责提交并连接。避免这两个按钮同时表达相同操作。
- 修改连接模式及 Wi-Fi 草稿不自动中断会话；用户明确提交后才重新连接。
- 地址处理、浏览器链接和自动连接开关保留既有的立即保存行为。
- 高级设置仍分别保存，涉及重连的设置提示生效时机；返回主页面保留尚未提交的连接草稿。
- 原首页的大幅介绍、重复连接说明、进入主设置的按钮及主设置中的独立“返回首页”操作不再作为合并页面的内容。
- 主页面不提供“退出应用”入口；实施时清理该入口不再使用的本项目绑定，保留连接区独立的“断开”操作。

## 新增网络模式：车载热点／第三方 AP

新增到无线网络来源选择中，与现有本机热点、同一局域网模式并列。它不替代“与 iPhone 的连接模式：无线／USB”。当前阶段仅记录设计，尚未增加运行时模式或连接代码。

此模式由车辆热点或第三方 AP 提供网络，不由安卓手机创建热点。无线连接时，安卓手机与 iPhone 使用该外部网络；车机浏览器也需要能通过此网络访问安卓手机。USB 连接时，iPhone 使用 USB 通道，外部网络仍可用于车机浏览器连接安卓手机。

- 热点／AP 名称、密码、安全类型、网络就绪状态和必要的 Wi-Fi 操作直接放在第一屏，不放入高级设置或折叠区。
- 使用目标网络中安卓手机的实际 IPv4 地址与当前服务端口生成浏览器连接链接，不硬套本机热点默认地址；必要时仍保留地址处理和授权操作。
- 网络地址已在统一地址区显示时，本模式区复用该显示，不再重复创建地址控件。
- 不显示“读取本机热点”操作，不要求安卓手机开启自己的热点。
- 提示 iPhone 加入目标网络；安卓手机尚未加入时提供系统 Wi-Fi 设置入口。应用保存连接配置，不把保存字段等同于系统已成功加入网络。
- 目标网络禁止设备互访时，显示网络不可达及检查设备互访设置的提示，不显示成配对码错误。
- 和现有“同一局域网”在网络拓扑上重合，实现时复用现有同网连接、凭据校验、地址获取和会话通道，避免新增重复控制器；本轮不擅自删除原模式。
- 汽车蓝牙音频路径沿用既有配置。

## A02 用途核对

A02 是此前清单对 `CarPlayHostActivity` 的原生投屏／连接准备界面的称呼，不是独立网页。

当前源码中它仍被调用：

- `DiPlayActivity.openProjection()` 启动该 Activity；连接手机及已有会话的入口会调用它。
- `CarPlayHostActivity.onCreate()` 接管已有会话或申请启动所需权限，启动 iPhone 连接流程。
- `buildContentView()` 保留测量与连接状态界面；手机模式通过 `PhoneBrowserReceiverUi` 禁用本地视频 Surface 并隐藏原生手势层。
- 同一 Activity 还承载主设置菜单，并通过 `TeslaBrowserLink` 服务手机＋浏览器模式。

收尾时同步了远程 `main` 的 `9ac0048` 更新：手机模式的 CarPlay 视频仅在浏览器显示，A02 的原生投屏画面与多指设置手势已经不属于该模式的显示流程。原生视频实现保留给上游车机兼容；Activity 的连接、会话接管、权限与恢复逻辑仍参与当前产品流程，不能整套删除。

后续可将手机＋浏览器模式的准备、阶段和重试提示收敛到统一主页面；这是界面收敛方向，并不表示本轮已合并 App 页面或删除其控制器。上游原生车机兼容实现仍按 `AGENTS.md` 保留。

## 实施时的代码清理要求

### 设置手势的范围

此前清单中的“手势”特指原生投屏界面中以 2／3／4 指下滑打开 App 设置的操作，不是 CarPlay 正常点击、拖动或滑动。

最新源码核对结果：手机模式通过 `PhoneBrowserReceiverUi` 隐藏原生手势层，网页触摸直接发送输入，不使用这项设置手势。`CarPlayHostActivity.onHostTouch()` 仍保留原生识别逻辑给兼容模式，`DiPlayActivity` 也仍生成手指数选择，后者需要按本设计清理产品入口。

本轮手机＋浏览器产品设计不再把“设置手势”列为主页面或高级设置选项。实施时移除该产品模式中无必要的设置入口与说明，清理确认不再使用的本项目绑定；保留上游原生车机兼容实现和 CarPlay 正常触摸通道。

### 合并页面与清理

合并页面时同步删除本项目新增的重复首页／主设置入口、重复控件、重复状态订阅以及失效样式、文案和测试引用。复用同一份连接配置与草稿，不维护两套相同状态。

保留上游文件和内部标识；不能直接删除 `DiPlayActivity` 或 `CarPlayHostActivity`，也不能误删仍在使用的连接、后台会话、权限和重连逻辑。涉及入口改动时检查活动会话接管与高级设置返回路径，完成 `AGENTS.md` 要求的网页及 Android 检查。
