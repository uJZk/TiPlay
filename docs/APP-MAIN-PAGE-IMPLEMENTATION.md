# 安卓端会话与设置边界

浏览器协作与关闭顺序见 [浏览器会话生命周期](TESLA_BROWSER.md#browser-session-lifecycle)。

## 启动与任务

桌面启动直接进入持有会话的 host，避免创建独立中转任务后留下空白预览窗口。旧首页意图和返回路径转到统一主页面；保留上游页面 API 不能重新暴露废弃产品入口。

主设置复用连接控制器、权限申请、会话接管和恢复流程。状态采用“CarPlay 搜索中／就绪／已连接／已禁用 | AirPlay 就绪／已禁用”的格式。手机选择、配置、蓝牙权限和网络要求单独显示。它不是阻塞自动重连的原生设置弹窗；手机产品不创建本地投屏 Surface，也不启用原生多指设置手势。

开机启动请求携带专用连接标记，使用已保存的连接模式。开机自启只决定是否启动应用；CarPlay 未禁用时持续尝试连接，显式重新连接会重建当前会话。

## 编辑与应用

连接草稿保留尚未通过校验的字段，窗口重建和高级设置返回不能丢弃它们。有效文本在停止输入后自动保存，离开主页面时应用有效输入；离散选择立即应用。连接草稿只保存连接参数，不能覆盖独立的视频设置。CarPlay 未禁用时，有效配置允许恢复自动连接。

高级页的帧率、HEVC、驾驶侧和 CarPlay 音频禁用在选择时立即保存，并通知持有会话的 host 重新读取参数、重新连接活动会话；通知不能将主页面带到前台。重建连接期间的后续修改仍需进入最新配置。禁用 CarPlay 时不自动连接。返回仅负责导航。系统权限操作、地址修改和浏览器端口设置独立生效，不应伪装成连接草稿。

`BrowserAdvancedSettings` 和 `BrowserNativeSettingsUi` 提供紧凑原生设置行与开关；旧分类入口统一到高级页。`BrowserCarPlayAudioSettings` 默认不禁用音频，`phoneBrowserAirPlayConfig()` 因此启用缓冲音乐与可用的麦克风。选择禁用后不接收 CarPlay 音频，保留 iPhone 的汽车蓝牙音频路径。此开关独立于保留的上游 `car_bluetooth_audio` 设置。

手动地址／端口修改立即更新手机地址或监听端口，不发送浏览器端点公告，也不延迟等待网页迁移。用户在网页断开后手动更新安卓端地址并连接，或打开新复制的配对链接；配对码保留。此流程不承诺自动恢复旧网页连接。

## 网络与兼容

安卓端热点和现有 Wi-Fi 分别复用上游手动热点与同网通道。旧外部网络来源恢复为现有 Wi-Fi，保留凭据，不能迁移成安卓端热点。网络配置在 USB 下仍然可见，因为浏览器网络独立于 iPhone 数据通道。

外部 Wi-Fi 安全类型与凭据独立持久化；旧记录没有显式类型时，从是否存在密码恢复开放或 WPA2。新选择进入运行配置和 iAP2 广告，能读取系统安全类型时校验实际协议；WPA3 过渡模式接受 PSK 或 SAE。开放类型使用空密码，切换类型时保留未提交密码。

网络附着不改变系统默认路由，也不主动创建或加入网络。不能要求互联网验证来判断本地 CarPlay 网络是否可用。网络名称不可读时保留手动配置路径；实际接口或地址丢失需要重建连接。

本项目新增功能置于产品专用文件，对上游会话实现只添加小钩子。保留上游文件、内部标识及兼容 API，以便后续合并；保留源码不构成维护原生车机产品界面或验收的承诺。

## 持续连接与 USB 优先

`BrowserCarPlaySettings` 保留“全部／无线／USB”选择，与控制器当前使用的两种传输分离。
全部模式在 Apple USB 设备插入时优先使用 USB，拔出后恢复无线，不能把临时传输保存成用户的模式选择。
USB 插拔和已选 iPhone 的蓝牙 ACL 连接采用系统事件；无控制器时每 16 秒检查一次已有配置与权限。
无线失败由现有会话恢复路径重建，蓝牙刚连接后间隔为 1、2、4、8、16 秒，随后固定 16 秒。
重复 ACL 事件不能不断重置快速重试序列；活动握手和会话不会被检查定时器打断。没有额外扫描或唤醒锁。
定时重试不重复申请定位、蓝牙或 VPN 授权；缺少这些权限时保留设置入口。蓝牙主动连接、热点和服务仍可能增加耗电，不能称为零耗电。

Root 和 Shizuku 只承担热点地址兼容职责；Root 另外提供显式热点名称和密码读取。2026-10-13 已移除主流程的特权 USB 授权尝试，USB 使用普通 Android 授权弹窗。保留的上游 USB 无障碍与 ADB 设置不作为手机产品入口。Shizuku 不显示热点名称和密码的读取按钮。
