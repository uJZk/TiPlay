# App 主页面实施

设计依据：[App 主页面设计](APP-MAIN-PAGE-DESIGN.md)。

## 页面和会话

正常桌面启动直接进入 `CarPlayHostActivity` 的统一主页面。该页面复用现有连接控制器、后台会话、权限申请和恢复流程，不使用原生设置弹窗的 `menuOpen` 状态阻塞自动重连。连接、状态、iPhone 选择、地址处理、浏览器配对、无线网络、开机自启、高级设置、语言和关于在一套页面中展示。车机浏览器位于连接分组之前；宽窗口将车机浏览器、连接和无线网络并排；窄窗口、矮窗口和大字体允许滚动，不隐藏必填字段。

顶部只保留一组连接操作，无线／USB 选择位于连接按钮之前。宽窗口将 iPhone 选择与连接模式并排，避免原生控件的默认高度将必填热点输入挤出首屏。未连接时连接；连接配置或 iPhone 选择有草稿时保存并重新连接；活动会话显示断开；失败时提供重试操作。没有独立 USB 快捷按钮、进入主设置按钮、返回首页按钮、视频参数预览或退出应用入口。

`BrowserConnectionDraft` 隔离未提交配置与运行中会话；返回高级设置和窗口重建保留草稿，提交时才保存并请求连接。高级设置修改帧率、HEVC 等参数仍独立保存，提交主页面草稿不会覆盖这些设置。地址处理和开机自启开关立即保存；开机自启使用 `AirPlayPersistence` 的 `autoStartOnBoot` 偏好，与打开 App 后的 `autoConnect` 独立。开机启动受 Android／厂商后台启动限制。浏览器页面地址不提供编辑入口；已保存的自定义 HTTPS 页面仍用于生成和复制连接链接。

断开由现有 host shutdown 释放资源，随后重建为未连接的主页面；本次断开不会立即触发自动连接。重新打开 App 时自动连接仍按既有持久化偏好生效，主页面不提供“打开时自动连接”开关。没有活动连接且自动连接关闭时，打开主页面不会自动发起连接或无线连接权限申请。

## 网络模式

安卓端热点映射上游 `MANUAL`；现有 Wi-Fi 映射 `EXISTING_WIFI`，覆盖车载热点和第三方 AP，复用同一凭据校验、`ExistingWifiManager` 和会话通道，保留上游枚举和配置接口。

旧的车载热点／第三方 AP 草稿来源恢复为现有 Wi-Fi；已保存的 `EXISTING_WIFI` 配置继续使用相同凭据。网络来源恢复不能将外部网络配置切换成安卓端热点。

仅安卓端热点显示读取热点及热点设置操作。热点地址处理方式紧随网络来源选择，仅无线模式的安卓端热点显示，现有 Wi-Fi 和 USB 隐藏。外部网络提供 SSID、密码、开放／WPA2 安全类型和必要的系统 Wi-Fi 入口；该支持范围与既有同网连接通道一致。保存配置不会自动加入系统 Wi-Fi。无法读取当前 SSID 时提示手动核对，不把权限导致的名称不可见误报成网络断开。网络错误提示检查目标网络和 AP 设备互访；不将其显示成配对码错误。

两种网络来源均先显示安全类型，再显示加密网络的密码字段。开放网络隐藏密码，保存和连接使用空密码；安全类型切换保留未提交的密码草稿，切回加密网络时恢复编辑内容。

安卓端热点的地址区显示实际网络 IPv4 和当前服务端口（“安卓地址”），不另建重复地址控件。返回系统设置时刷新地址和浏览器服务信息。USB 隐藏无需填写的无线凭据；车机浏览器继续使用安卓端当前网络。

高级设置不提供搜索按钮，保留上游搜索 API。权限帮助中的忽略电池优化操作打开系统电池优化列表；不可用时回退应用详情，是否放行由系统设置决定。

## 清理和上游兼容

`AGENTS.md` 已加入用户原文：“在不影响复用上游后续代码更新可能的前提下，移除冗余代码”。

替换 TiPlay 新增的独立日常设置布局，移除它的退出、返回、底部重复连接操作和预览绑定。手机产品的高级设置隐藏多指打开设置入口，正常 CarPlay 触摸不变。保留 `DiPlayActivity` 的上游页面 API、上游原生文件及内部标识、共享权限及会话控制；不删除上游文件或改名内部标识。

旧浏览器弹窗测试已由主页面、草稿和网络来源行为测试替代。核对发现旧首页布局和原生菜单 UI 测试文件来自上游，因此保留其原始源码，由 `gradle/tiplay-product-tests.gradle.kts` 从 TiPlay 检查中排除旧首页／弹窗用例。手机产品的主页面、运行时隔离、USB、权限和会话回归在新增的 `BrowserMainPageTest`、`BrowserMainHostTest` 中验证。本项目不考虑原生车机，不维护原生产品入口或验收；保留上游源码仅为后续合并。
