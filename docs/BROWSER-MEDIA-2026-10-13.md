# 手机与网页媒体调整

主设置将热点端点收拢到配对码下：Root、Shizuku、VPN 显示可编辑按钮，普通方式显示一行地址文字。TiPlay 模式选择不再有总说明，选项说明保留必要的权限与 VPN 限制。删除 Root/Shizuku 自动批准 USB 的产品尝试和误导文案；系统 USB 权限流程不变。

高级设置的返回按钮下方是全局帧率，随后是 CarPlay、AirPlay、诊断和权限。禁用 CarPlay 音频与 HEVC 位于 CarPlay，不再单独显示音频、视频栏。AirPlay 标题去掉实验性后缀。缓冲音乐不再可配置，手机与网页会话在声音启用时始终提供 `mainBuffered` 能力；只有 iPhone 接受该能力并建立类型 103 时才进入缓冲通道。保留上游原生设置 API 供兼容合并，不作为产品入口。

## CarPlay 音频通道

传输类型与声音用途是两个维度，不能用类型 100 当作音乐的唯一身份。

| 声音用途 | 闲时网页播放 | 蓝牙电话通道期间 |
| --- | --- | --- |
| 媒体／音乐 | 通道 0；安卓解密、解码，网页按源时间呈现；提示时音乐增益为 0.2。 | 继续由网页播放，保留队列与解码器。 |
| 导航／默认引导 | 通道 1；独立实时队列、时钟和 epoch。 | 仅走蓝牙单声道混音，**固定 0.25 增益**，不取决于此刻是否有通话或 Siri 声音。 |
| 通话下行 | 通道 2；实时队列。 | 仅走蓝牙，保留原增益。 |
| Siri 下行 | 通道 3；实时队列。 | 仅走蓝牙，保留原增益。 |
| 警报／其他提示 | 通道 4／默认映射，压低网页音乐。 | 继续由网页播放，不进入蓝牙混音。 |
| 缓冲音乐（传输类型 103） | TCP 提前发送 AAC-LC，安卓解密／解码并施加背压，网页持有播放缓冲。 | 延续同一网页缓冲与背压，不因蓝牙路由丢弃或重建。 |
| 麦克风上行 | 不采集。 | 安卓 AudioRecord 从已确认的 SCO 输入采集；按协商速率重采样、编码 LPCM／Opus、加密后用 UDP 发送给 iPhone。 |

导航白名单含 `navigation`、低速流的 `default`／`compatibility`，对应现有手机通道映射。102／103 媒体流的兼容音频、`media`、`alert` 和未知用途不进入电话混音。普通 UDP 仍保留至多 30 ms／4 包重排和 24 包解码队列；TCP 不做 UDP 重排。蓝牙混音各流只保留最新 160 ms，按 20 ms 块播放，求平均折叠立体声、重采样、固定衰减导航后限幅。较高采样率向下转换时先低通滤波；48 kHz 单声道混音由 Android 转换到 HFP 实际协商的窄带／宽带速率。

## 按需蓝牙电话通道

无麦克风需求时，CarPlay 声音由网页播放。iPhone 请求通话／Siri 录音时，安卓进入 `MODE_IN_COMMUNICATION` 并请求 HFP/SCO。Android 12+ 使用 `availableCommunicationDevices`／`setCommunicationDevice`，旧版通过 HEADSET 查询和 SCO 广播确认；只选唯一可用的 HFP 设备，不猜测多个耳机，也不覆盖系统已有的通话通道。

麦克风需求期间，通话／Siri／导航只走蓝牙，不向网页重复输出；单独导航在无麦克风需求时仍由网页播放。音乐、缓冲音乐、警报／其他提示及 AirPlay 镜像／URL 视频声音继续由网页播放，不随连接、失败或释放阶段全局静音。只有通信设备、AudioRecord 的实际输入及 AudioTrack 的实际输出都确认是蓝牙 SCO 后，才打开上行与语音播放。连接失败、权限撤回、设备脱离或音频焦点被抢占时停止设备、释放焦点并报告错误；不使用手机麦克风或网页录音兜底。结束需求后等待实际 SCO 释放，再把语音／引导归属交回网页；释放超时保留失败状态并继续观察，不能把请求成功当作硬件已释放。

路由切换只改变通话／Siri／导航的归属，不清空音乐、缓冲音乐或 AirPlay 队列，也不因此替换其解码 worker 或 codec。`/audio` 中空的类型 5 记录及控制状态携带路由 revision，网页拒绝旧状态；更新路由不替换承载音乐的 HTTP body。路由拥有者与显示拥有者分开，AirPlay 接管显示期间仍等待 SCO 清理。重连的新 CarPlay tap 等待旧 tap 释放后才启动自己的通道。

同时有通话和 Siri 录音需求时，通话优先；结束其中一项不关闭另一项。恢复同一个需求时保留 RTP／加密计数器，避免复用 ChaCha nonce，并保持已协商的 Siri／通话 RTP 时钟。

## 权限与回声处理

按用户最新决定，网页录音、原生 AEC 检测、Speex WASM、参考 PCM 上传和安卓软件 AEC 兜底全部退出产品链路。网页只创建播放 AudioWorklet，不调用 `getUserMedia` 或查询麦克风权限。旧权限／声音横幅、DOM、CSS 和显示文案均删除；路由失败保留在安卓日志、结构化状态和诊断中。网页声音仍可在首次触摸／按键后恢复浏览器要求的用户激活。

安卓首次连接在前台请求麦克风权限，高级设置也提供权限行。无授权时仍允许网页播放，CarPlay 不声明麦克风能力；授权或撤回后重连协商。前台连接服务在获授权且声音启用时声明 microphone 类型，为随后熄屏／后台的按需录音保留 Android 允许的访问。它不提前创建录音设备；从后台首次启动 microphone 前台服务仍受 Android 平台限制。

回声处理依赖车机 HFP 通话链路，TiPlay 不添加第二层 AEC。保留上游原生 Speex／MicrophoneUplink 仅作兼容合并。删除 TiPlay 的旧 `/microphone` 接口、麦克风状态及上传统计；浏览器 CSP 同时撤掉 WASM 执行许可，播放 Worklet 无输入端口。访问安卓局域网的浏览器授权仍可能需要。车机实际 AEC 效果与 HFP 接通／释放行为仍须实测。

## AirPlay URL 视频

[AirPlay 文档](AIRPLAY.md)记录当前协议和资源边界。Video.js 8.24.1 随站点缓存发布，网页负责播放、控制、缓冲与音画同步；后续 Canvas 实现将底层 HTML video 隐藏，仅把画面绘制到独立 Canvas（详见 AirPlay 文档），声音和控制仍归 Video.js；无全屏按钮，缓冲使用原生加载图标。安卓端的 Media3 URL 播放、视频转码、URL 视频专用 PCM 输出、提交／PTS 映射，以及网页 URL 视频延迟模式已删除。图片保留必要的画布编码，镜像／CarPlay 保留实时调度。Debug 删除预期／提交时间一行，保留编码、当前 FPS、呈现偏差中间 90% 均值和最高 5% 均值。

资源只通过配对验证的播放 ID、资源 ID 暴露；清单有大小上限，媒体采用流式转发，保留 Range，跳转与子资源继续校验协议。当前 iPhone 对端的 HTTP(S) 资源跳过反代，网页直连；`mlhls` 等应用 URL 和 FCUP 内容仍通过安卓交接。直连要求 iPhone 的 HTTP 服务提供可用的 CORS、证书及局域网路径；USB 私网地址不保证车载浏览器可达。

全局帧率保存到同一个设置并用于 CarPlay 与镜像协商。活动镜像可重新协商；URL 视频不重建播放器或改变源帧率。
