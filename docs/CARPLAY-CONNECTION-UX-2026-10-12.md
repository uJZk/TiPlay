# CarPlay 持续连接与模式设置

本文记录 2026-10-12 的实现和验证。2026-10-13 已移除下文记载的 Root/Shizuku 特权 USB 授权尝试；当前手机流程使用普通 Android USB 授权弹窗。模式保留热点地址兼容行为，Root 保留热点名称／密码读取，Shizuku 仍不显示读取按钮。高级页随后改为紧凑原生设置行，并加入独立的 CarPlay 音频禁用开关，见[当前页面契约](APP-MAIN-PAGE-DESIGN.md)。下文测试和虚拟机结果保留为当时证据。

TiPlay 主页面移除“连接手机”，保留“重新连接 CarPlay”。高级设置增加独立的“禁用 CarPlay”；未禁用时自动启动并持续恢复连接。开机选项改为“开机自启”。AirPlay 默认接收与独立禁用设置保持原有行为。

状态使用“CarPlay 搜索中／就绪／已连接／已禁用 | AirPlay 就绪／已禁用”，配置与权限要求保留在状态下方。TiPlay 模式位于 CarPlay 连接模式之前，iPhone 选择行位于 CarPlay 模式下方，仅无线或全部模式需要时显示。

## 连接策略

新增“全部（USB 优先）”，原无线和 USB 选择继续保留。全部模式监听 USB 插拔，优先使用已插入的 Apple USB 设备，拔出后恢复无线；当前传输不会覆盖用户保存的全部模式。

USB 主要等待系统插拔事件。无线会主动连接已配对的 iPhone，并非完全被动接收，也不持续扫描附近设备。已选 iPhone 的蓝牙刚连接后，失败重试间隔为 1、2、4、8、16 秒，之后固定 16 秒；重复 ACL 事件不能不断重置快速重试。蓝牙到达时会提前已有的慢重试。正在握手或连接成功时，检查定时器不打断会话。等待 iPhone 或进入无线监听时显示 CarPlay 就绪；主动建连时显示搜索中。

未运行控制器时每 16 秒检查已保存配置与已有权限；缺少定位、蓝牙或 VPN 授权时，定时检查不循环申请这些权限。禁用 CarPlay 取消待执行重试、关闭活动控制器并阻止再次启动；重新启用恢复连接。未增加扫描或唤醒锁，但蓝牙主动建连、热点和接收服务仍有耗电，实际电量需以后实机测量。

## TiPlay 模式与权限

原“热点地址修改”改为“TiPlay 模式”，“无”改为“标准”。所有模式选项显示自己的说明，主描述说明地址兼容与 USB 权限行为。

Root 模式支持现有热点名称／密码读取，并尝试启用只确认 TiPlay 系统 USB 弹窗的无障碍服务。固定脚本验证包名，保留其他已启用服务；单个进程不反复请求失败的 Root 设置。

Shizuku 模式保留地址兼容实现，并通过已有授权尝试调用系统 USB 服务，为当前 TiPlay UID 授予当前设备权限。系统或 ROM 拒绝时，普通 USB 授权弹窗继续可用。当前 Shizuku 热点配置读取无法作为可靠产品功能提供，主页面隐藏读取按钮，名称与密码手动输入；这不意味着任何 Shizuku 实现都无法读取。

标准模式不修改地址。VPN 模式保留原有地址范围、其他 VPN 冲突和有线 CarPlay VPN 互斥限制。所有新增文案及模式说明覆盖现有七种语言。
