# Browser URL playback boundaries

Mediabunny supplies media tracks and decoded WebCodecs samples. TiPlay owns Canvas,
Web Audio output, playback clock, buffering and seeking. Video.js owns native
controls, its skin and automatic hiding. This separation lets URL-video timing
change independently of Android's upstream protocol implementation.

The Video.js media adapter must expose measured media state and events from the
TiPlay engine. A separate HTML video element would introduce another playback
clock and invalidate buffer, seek and iPhone status feedback. Native controls and
iPhone directives act on the same engine. Stop ends the current AirPlay item;
pause preserves it. Playback IDs and independent seek revisions isolate stale
reports and ensure later pause/play commands cannot undo a seek.

Older APK directives omit playback rate. Their pause/play commands must preserve
the speed selected in the browser; an explicit finite rate can replace it. Accurate
iPhone rate feedback requires the Android rate-reporting implementation as well
as the updated page.

Audio playback leads the URL-video clock; a silent video uses a monotonic clock.
Decoded buffering is limited and reported as playable time ranges, using the
audio/video intersection. Underrun freezes both streams. Source metadata and the
HLS timeline survive pause, seek and speed changes; stopped/replaced sources abort
their requests and release decoders, samples, audio nodes and GPU resources.

Variable speed requires audio tempo processing as well as a different video
schedule. SoundTouch preserves pitch. Supported surround layouts are downmixed
for tempo processing so central dialogue is retained; undefined layouts fail
explicitly. WebCodecs codec support must be checked on the actual browser. A
working native HTML media decoder does not prove WebCodecs audio/video support.

Captions combine an independent, cancellable subtitle source with observation of
already fetched media and a bounded encoded-video packet sink. The maintained
hls.js parsers supply WebVTT, timestamp conversion, SEI extraction and CEA-608;
TiPlay adds BMFF `wvtt`/`stpp`/`tx3g` sample demux and CEA-708 text services.
HLS-TS and CMAF/fMP4 HLS work through the same media clock. Identity AES-128
whole-segment encryption supports rotating keys, explicit/sequence IVs and
encrypted initialization segments; encrypted mixed media is inspected without
refetching its audio/video payload. These capabilities require accessible source
resources and keys, and do not provide FairPlay or other DRM authorization.

Cue activation uses the engine's frame clock, because throttled UI time updates
can skip short cues. Packet lookahead cannot display captions early. New playback
generations reset caption state and read from the preceding keyframe; early MP4
observations rebase after the source origin becomes known. Mixed HLS fMP4 maps
its audio/video presentation timestamps to the logical playlist segment position. Discovery cannot delay
video preparation and caption failure cannot terminate playable video. Video.js
shows the subtitle button only for a successfully parsed real track; an empty
initial cue window alone does not make a valid track unavailable. A bounded
initial probe permits selection of non-default tracks without continuously
fetching disabled tracks. Only plain text reaches the overlay; TTML image/layout
and CEA-708 window styling are not rendered. See [AirPlay subtitle contracts](AIRPLAY.md#url-视频字幕)
for timeline, bounds and Apple's WebVTT-only AirPlay 2 TV profile.

All runtime code and styles are self-hosted. Authoritative versions and integrity
are in the [vendor build inputs](../scripts/videojs/package-lock.json); provenance
and rebuild rules are in the [control bundle](../site/play/vendor/videojs/README.md)
and [media bundle](../site/play/vendor/mediabunny/README.md). Any runtime asset change
must update the complete service-worker manifest and cache identity. Phone media
requests remain outside the page cache.

Acceptance requires actual decoded moving pictures, seeking while paused,
buffer/rate feedback, subtitle timing and language selection, Bluetooth mute,
ended/replacement/photo handoff, stale callback isolation and offline module
loading. Desktop browser checks do not establish vehicle performance, acoustic
audio/video synchronization, iPhone resource accessibility or recovery after
live segments have expired on the source server.
