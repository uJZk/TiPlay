# Video.js v10 migration — 2026-10-14

TiPlay's AirPlay URL-video player now uses Video.js **10.1.0**. The migration is separate
from the [full DiPlay source sync](UPSTREAM-SYNC-2026-10-14.md), making future playback
updates independent of Android upstream merges.

## Implementation

- Replace the v8 `videojs()`/Component API with `@videojs/html` player and UI custom
  elements, composed in owned `site/play/videojs-player.js`.
- MP4 uses a native video element. HLS uses official `@videojs/hlsjs-video@10.1.0`
  with `hls.js@1.6.19`, preferring MSE and retaining the adapter's native fallback.
  VHS is removed.
- Retain authenticated phone resource proxying and direct iPhone URLs, media ID and
  revision isolation, independent seek revisions, actual browser clock/buffer reports,
  iPhone play/pause/seek, car Bluetooth mute enforcement and Stop casting.
- Continue rendering pictures through the existing WebGL/2D Canvas. The HLS adapter
  keeps its own native video target; Canvas observes that target without replacing it.
  Native/HLS active caption cues render as plain text above the canvas, with the v10
  caption toggle. WebVTT formatting is flattened; source cue markup is not inserted.
- v10 controls supply play/pause/replay, ten-second seek buttons, time/volume sliders,
  mute, caption toggle, loading state and automatic control hiding. Fullscreen and PiP
  remain absent. Chinese labels come from the bundled v10 locale.
- Stop, source replacement, photo handoff and disposal release Canvas callbacks, caption
  listeners, progressive downloads and the HLS engine. Detached media callbacks cannot
  update a replacement player.

## Dependency and offline delivery

The [vendor record](../site/play/vendor/videojs/README.md) describes the exact npm
versions, published integrity and local build. Build inputs and lockfile live under
`scripts/videojs/`; node_modules are ignored. The generated ESM bundle and all
third-party license texts ship under `site/play/vendor/videojs/`.

No runtime CDN is used. The service-worker cache is `v37`; its manifest includes the
bundle, player adapter, caption layer and notices. The cache preserves the pairing-link
fragment behavior and never caches phone requests or download pages.

Video.js v10's documented browser support begins at Chrome/Edge 111, Firefox 121 and
Safari/iOS 16.4. Chromium automated tests passed; actual car browser and Safari acceptance
remain device checks. Existing TiPlay WebCodecs requirements still apply to mirroring.

## Validation

- Browser unit tests: 116 passed with Node 22.
- Chromium page E2E: reconnect, theme, viewport and offline reopening passed. Loading
  both v10 and the HLS adapter after the page server stopped also passed.
- URL-video E2E: MP4 WebGL, forced 2D, no-requestVideoFrameCallback fallback and HLS
  passed. Checks cover moving pixels, hidden native picture, source-resolution cap,
  letterboxing, pause/seek revision behavior, actual seek-slider clicks, resize, WebGL
  context restoration, Bluetooth mute enforcement/restoration, caption display/toggle,
  Chinese labels, Stop casting, ended-frame quiescence, replacement, photo handoff,
  failure revision reporting and disposal, without unexpected browser exceptions.
- Vendor rebuild, public-tree scan and source whitespace checks excluding unchanged
  upstream Concentus CRLF source passed. The DiPlay sync record contains Android CI.

The URL-video harness uses a generated 320×180 H.264/AAC clip and HLS playlist, supplied
through `TEST_VIDEO_MP4` and `TEST_VIDEO_HLS` to `tests/web-e2e/airplay-video.mjs`.
There is no new APK version, push or deployment in this source migration.
