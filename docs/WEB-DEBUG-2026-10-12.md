# 浏览器主题、Debug 与安卓设置修复

日期：2026-10-12。实施记录在 `sweep-2026-10-12/`。用户后续调用 `tie-up`，授权提交、合并、推送及已有 Pages 部署；提交、合并、推送及成功部署记录见 `sweep-2026-10-12/TIE-UP.md`。

浏览器主题变化立即通过已有认证控制通道发送，并在重连及每次周期统计中携带布尔 `themeDark`，避免同类统计合并丢失主题。安卓在主线程缓存及分发；Activity 销毁而会话仍保留时，使用现有命令执行器更新当前会话，拒绝旧会话及关闭后的命令。上游类、包名、资源及持久化键保持不变。

Debug 胶囊现为四字段：编码、中间 90% 平均 FPS、中间 90% 平均延迟、最慢 5% 平均延迟。统计窗口仍为最近五秒，去掉两端各 5% 后平均，边界按比例加权。FPS 以平均帧间隔的倒数计算；最慢 5% FPS 留在完整诊断中，不占横幅。按用户后续要求，恢复不显示硬/软信息，例如 `HEVC · 60 fps · 5 ms · 34 ms`。WebCodecs 不公开实际选择的硬件/软件解码实现，不能把诊断中的 `prefer-hardware` 配置当成硬解证明。每个统计快照复用排序结果，数组复制及排序从四次减为两次；未进行端到端性能基准。此次显示调整将 Service Worker 缓存升为 v16。

AirPlay SETUP 未提供或提供零 timingPort 时，以前 App 只回复 iPhone 主动发出的计时请求，自己的同步状态一直不可用。现在保留已知 RTSP 对端地址，从该对端的请求学习计时端点，再沿用原有四时间戳交换完成同步。不会用安卓收帧时间替换源帧时间。新增 UDP 回归覆盖异钟域映射，浏览器回归覆盖同步帧时间传到绘制以及无同步仍不造数。没有受影响 iPhone 的 SETUP 抓包，不能断言该路径就是所有实机 `—` 的原因；时钟过期、未来帧时间等仍会拒绝。浏览器诊断中的 timingRecords/timingRejected 区分未收到源时间与浏览器拒绝时间样本。测量是同步帧时间到 canvas 提交的估计值，未验证采集到物理屏幕出光。

安卓两位独立 UI/UX 审查者分别检查布局和生命周期。前三个连接按钮统一间距、宽度及最小触摸高度；地址/链接卡刷新时若页面已挂载，立即启动探测和监听，避免返回后地址消失及查询停住。查找提示统一为“正在查找本机热点地址…”；VPN 授权通过有结果接收者的启动方式调用，沿用恢复时的服务同步。热点信息读取显示进行中、成功、仅名称或无法读取，保留读取期间输入。普通 Android 应用在部分系统上没有读热点密码的权限，仍需手动输入，不绕过平台权限。

空闲状态先检查 iPhone、配置、蓝牙权限/开关及已知热点/Wi-Fi条件，再显示“一切就绪”；正在连接、已连接、停止中状态保持会话含义。USB 不要求事先选择蓝牙 iPhone。

## 后续：移除 App 内置网页

按用户后续要求，删除 `BundleBrowserPage` 打包任务、安卓网页资源加载器、本地 `/play/` 静态服务和未使用的本地网页链接辅助函数。App 仅提供 `/hello`、`/video`、`/control`、`/bye` 协议接口；`/`、`/play`、`/play/*` 返回 404。网页由独立 HTTPS 站点托管，离线重开使用浏览器此前保存的 Service Worker 缓存。网页地址处理不再推断 HTTP 页面主机就是手机地址，统一使用 `?t=`、保存的地址或默认地址。

测试已改为检查协议入口和不存在的网页入口，实际 App 服务器 E2E 使用独立网页服务器。移除并整合 main 后的最终验证通过：安卓 2268 项测试（shared 1219、common 1045、home 4，无失败/错误/跳过），三项 Lint 和三个 debug 构建；浏览器 65 项测试和两套 E2E 全部通过。三个 APK 的 `assets/play/` 条目均为零。下方完整记录保留移除前的 sweep 结果，最终证据见 `sweep-2026-10-12/TIE-UP.md`。
