# TiPlay 网页配对与门户契约

网页的配对、等待／重连和 CarPlay 是同一页面的状态，不创建独立设置面板。“设置”返回配对门户并保留当前会话；此时提交操作只恢复 CarPlay 画面。更换连接信息需要先断开，再编辑并连接。

## 输入与操作

配对码和安卓端地址直接显示，不放在折叠区；未连接时允许编辑，连接期间禁用这两个输入。连接在上，断开在连接按钮下面；断开仅在有连接可停止时显示。错误紧邻连接操作，不能把网络不可达显示成配对码错误。

门户与等待／重连页面共用预渲染背景，避免车载浏览器在视频播放时承担运行时模糊成本。具体样式和尺寸以网页源码为准，不在文档复制像素清单。

地址与配对码可以手动填写，也可以从安卓端复制的完整链接导入。安卓端复制的 HTTPS 完整链接通过查询参数 `t=地址:端口` 传递端点，配对码使用片段 `#c=码`；片段不能改为查询参数，以免发送给静态页面服务器。浏览器也接受省略默认端口或默认端点的链接；安卓端本地 HTTP 页面使用自身地址，无需 `t`。

浏览器导入配对码后保存并移除片段。书签应在导入完成后建立，以免保存配对码。改变配对码后必须重新输入或打开新链接；书签不能绕过新配对码。

## 会话状态

返回门户不是断开：保留视频连接与后台恢复能力。点按 CarPlay 内的 TiPlay 图标返回门户，重新进入画面不应创建第二次连接。

主动断开停止视频、控制和自动重试；用户再次连接才恢复。另一浏览器成功配对时可以接管画面，原浏览器明确说明接管状态。

浏览器 viewport、显示替换及服务发现关闭顺序遵循 [浏览器会话生命周期](TESLA_BROWSER.md#browser-session-lifecycle)。改变原生 CarPlay 尺寸需要新的 iPhone 显示会话，前端不能承诺仅通过 CSS 完成原生分辨率变化。

## Debug

Debug 的开关保存选择且不重连。统计根据实际画布提交和同步帧时间计算，不代表物理屏幕呈现时刻；同步信息缺失或过期时显示未知，不能用接收时间替代端到端延迟。具体统计窗口和字段定义以实现与测试为权威来源。
