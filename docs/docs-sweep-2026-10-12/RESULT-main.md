## Remaining conflicts and validation limits

- Reachable HEVC is labeled `HEVC (H.265)` through `settings_browser_hevc_title` in `BrowserAdvancedPage` and every locale's `strings_browser_revision.xml`. `AGENTS.md` requires an experimental title suffix, and the compatibility builder `BrowserAdvancedSettings` still uses `settings_hevc_experimental`. This is a source/UI policy conflict; no code/string changes are authorized for this task. The owned contracts make no claim that the current label has the suffix.
- Boot launch and connection, Root/Shizuku hotspot reads, car-browser background recovery and actual hotspot reachability remain device/platform dependent. Source and local tests cannot establish behavior on the target car. The docs retain that distinction rather than asserting fresh device validation.
- Network credential validation is a wireless iPhone setup contract: `BrowserConnectionDraft.validationError()` returns early for USB, while browser network fields remain visible and saved. Existing prose does not require wireless credentials for USB; avoid reading its security paragraph as a guarantee that every USB submission probes Wi-Fi security.
- The launcher manifest goes directly to `CarPlayHostActivity`, and legacy home intents redirect/finish (`BrowserMainEntryTest`). This supports the intended lifecycle, but eliminating every OEM task-preview anomaly is not established by local tests.
