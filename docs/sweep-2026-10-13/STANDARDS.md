# Code standards

Source of truth for this sweep; reuse AGENTS.md and docs/Upstream.md requirements.

1. Scope: only files listed in SCOPE.md, and only TiPlay additions/modified hunks in the recorded incremental scope in inherited files. Preserve upstream identifiers, files, formatting and internal names. Do not rename/move/delete inherited code. No feature additions or behavior changes.
2. Kotlin: follow neighboring four-space formatting and existing naming; remove demonstrably unused imports, variables and private helpers only in fork-owned code. Prefer named constants for duplicated protocol values where semantics are identical. Avoid broad structural refactors of upstream hooks.
3. Lifecycle/concurrency: preserve locking, callback order, thread affinity, cancellation, timeout values and resource ownership. Do not alter network fallback or media queue policies.
4. Error handling/security: preserve observable exceptions and fallback results; keep diagnostic redaction; never print credentials or introduce secrets; no new dependencies. Behavioral defects go in Open decisions, not fixes.
5. JS/Python/Java: preserve current module style, public exports, protocol format and persisted keys; remove proven dead locals/imports, redundant exact duplicate expressions and stale comments only when semantics are unchanged. No unrequested formatting churn.
6. Android/settings: retain phone-browser defaults and head-unit gates, existing preference keys, reconnect consent, settings categories and translations. User-visible product name TiPlay; internal DiPlay names and credits unchanged. Resource edits only for concrete structural defects, not copy redesign.
7. Tests: retain meaningful behavioral assertions; do not add tests mirroring mechanical cleanup. Run relevant existing checks. Coordinator runs AGENTS.md Android CI command, node --test tests/web/*.test.mjs and python3 scripts/check_public_tree.py. Report unavailable infrastructure precisely.
8. Generated/vendored files: no manual changes to generated locale HTML, packaged binaries, native/vendor code or build output. New features go to docs/todo.md; behavioral decisions stay in sweep README.
9. Performance (explicit user requirement): inspect fork-owned video/touch/audio hot paths for avoidable per-frame allocations/copies, repeated parsing/work, blocking I/O on UI or media threads, lock contention, unbounded collections and missing resource release. Apply only behavior-preserving improvements backed by code evidence and relevant checks; preserve ownership, ordering and thread safety. Record tradeoffs requiring queue policy, timeouts, protocol or lifecycle changes as Open decisions. Do not claim performance gains without measurements. Review init/settings paths proportionately; avoid speculative micro-optimizations.


10. Test retirement (explicit user request): remove TiPlay-owned one-off acceptance or source-shape tests for completed/retired single-entry experiments only when current behavioral coverage exists or the tested contract is retired. Do not delete regression tests merely because their feature is complete. Retain upstream tests and all shared session/phone-browser behavior coverage. Record removed test names, reason and retained coverage.

Model mapping: Sonnet/Opus are unavailable in this toolset. Use gpt-6.1-sol for mechanical work; gpt-6-astra for lifecycle/performance and ambiguous test-retirement judgment. No prior-session repair authorization is inherited.

11. Native JNI: only TiPlay wrapper/build hooks are in scope; retain upstream/vendored C and reply tables unchanged. Preserve size/mode validation and null/error results, avoid shared scratch state, no handshake/cryptography changes. Validate with scripts/test_airplay_native.py.

12. Current-session authorized retirement: per RETIREMENT-SCOPE.md, remove single-Bonjour trial and only its dedicated coverage, restoring the existing independent ordinary AirPlay/CarPlay default paths for all devices. This is the explicitly requested behavior change; unrelated performance/lifecycle behavior changes remain Open decisions. Preserve upstream files and normal session/media regressions. Existing UDP release checks may await real wildcard rebind up to 1 second because shutdown intentionally does not join worker threads; catch only BindException, fail at deadline, retain both port and subsequent video assertions.

13. Current-session authorized risk repairs: follow REPAIR-SCOPE.md for consistent tap-map locking, network I/O outside receiver ownership and promptly cancellable generation-safe buffered audio publication. Preserve incoming main Bluetooth routing and media behavior. Meaningful deterministic concurrency regressions are required; these are authorized behavior fixes, not unrelated cleanup.

14. User-requested post-merge cleanup: INTEGRATION-SCOPE.md supplements initial SCOPE.md and REPAIR-SCOPE.md. Clean TiPlay-owned incoming code and merged session hunks only, preserve incoming Bluetooth/media/public interfaces and retired trial state. C1 excludes R1 files; C2 excludes R2–R3 files; C3 owns incoming browser/tests/build workflow hunks. No formatting churn, speculative optimizations or test removal merely because features are complete. New/proposed unrelated behavior fixes stay Open decisions.

15. User-authorized post-merge retired remnants: RETIRED-SCOPE.md extends support-file review beyond incoming diff where those files exclusively implement newly retired TiPlay paths. Record exact additional file paths and use/call evidence before edits. Retain inherited upstream compatibility files and active shared/browser regressions. Parallel owners remain disjoint; R1–R3 files cannot be edited by residue reviewers.
