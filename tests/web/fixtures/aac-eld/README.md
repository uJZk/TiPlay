# Synthetic AAC-ELD tones

These are prefixes of the `fixtures/<rate>-<channels>-<frameLength>-1.bin` files
generated by `fixtures.cpp` in the supplied
[corresponding source archive](../../../../site/play/vendor/aac-eld/aac-eld-source.zip).
The generator uses the complete unmodified FDK encoder;
they contain no captured music or user traffic. The source and decoder license
are retained in the [vendor distribution](../../../../site/play/vendor/aac-eld/README.md).

Each container stores a little-endian unsigned 32-bit byte length followed by
that many bytes. The first segment is the four-byte AudioSpecificConfig; the
remaining twelve segments are complete raw access units. Filenames identify
sample rate, channel count and samples per channel. There is no RTP framing.

To reproduce a fixture, build the archive's complete FDK native library, compile
and run `fixtures.cpp` against it, and retain the generated stream through the end
of its thirteenth length-prefixed segment without changing those bytes. These small
fixtures exercise all supported rate/channel/frame-length combinations and
initial decoder history; they do not establish vehicle audio performance.

`pcm-sha256.json` pins the concatenated twelve PCM16 outputs for each profile
from the independently executed pre-migration asm.js decoder at browser source
commit `5ea829adf39d87bb1d3fc4360528fe5f3c590d7a`. They are fixed comparison values,
not computed by the WASM decoder under test. Both the Node integration and actual
Chromium module-worker checks require the shipped WASM to match all eight hashes.
